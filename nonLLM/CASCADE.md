# Config A cascade with non-LLM routing

`cascade.py` trains the existing five classifier families (majority, logistic
regression, linear SVM, multinomial NB and random forest). It uses the supplied
Config A retrieval coverage labels and QA outcome labels, mapping X to W.
Retrieval sees the weak retrieval evidence instead of the full pool. One shared
QA classifier learns from both retrieval branches. Both stages cap passage text
at 600 characters. TF-IDF is fitted on training inputs only; numerical features
use question/evidence statistics and, when supplied, weak-answer statistics.
Gold answers, coverage annotations and measured outcomes are not features.

For each family, stage hyperparameters are chosen by validation ROC AUC. The
two decision thresholds are swept jointly on validation; the operating point
is the cheapest reaching 95% of direct-SS validation accuracy. The family is
also chosen on validation under this rule. The thresholds and selected models
are saved before scoring test inputs. Only the selected family is evaluated
on test. Test has been evaluated in earlier experiments, so this is a frozen
replay on the existing benchmark, not a first-ever sealed-test claim.

All runs replay Config A outcomes rather than generating new answers. Escalation
cost includes both the weak call already performed and the additional strong
call. Reports distinguish direct SS (strong calls only) from cascade SS (weak
plus strong at both stages). Router CPU overhead is excluded from modeled costs.
SVM uses decision margins rather than calibrated probabilities.

## Run with currently available data

This is explicitly an **input ablation**: weak answers are absent. Costs use
Config A's flat parameter-ratio proxy (weak=1, strong=4.7), not measured tokens.
It must not be presented as a complete reproduction of the author's experiment.

```bash
cd ${WORKSPACE}/STAIR/nonLLM
env OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  python -u cascade.py \
  --labels-root ${WORKSPACE}/Labels/slr_labels_configA \
  --without-weak-answer --flat-costs \
  --out ${WORKSPACE}/runs/nonllm_cascade_configA_ablation_v1
```

Use a new output directory for every run. Outputs include `REPORT.md`,
`results.json`, `theta_lock.json`, validation frontier CSVs, test predictions,
and the selected `ret.joblib` / `qa.joblib` bundles. Input SHA-256 hashes are
recorded in `config.json`. This script does not start GPU services.

## Full inputs

Replace `--without-weak-answer --flat-costs` with:

```bash
--qa-weak /absolute/path/to/ConfigA/qa_weak.jsonl \
--token-costs /absolute/path/to/ConfigA/token_costs.json
```

The weak-answer cache must have all 14,810 keys, stored as JSONL
`{"k": "idx|weak", "v": "answer"}` and `{"k": "idx|strong", "v": "answer"}`.
The suffix names the retrieval branch; both values are weak-answerer outputs.
The cost file is the output of Config A `token_costs.py` and contains six
`gate_eval_constants`. These files must come from the **same Config A grid**;
do not mix answers generated by the local Base GGUF pipeline with this
Instruct grid. The two supplied archives do not include those complete caches.
If regenerating model outputs, regenerate and evaluate the matching outcomes
as well; greedy generation alone does not establish identity across environments.

## Checks

```bash
python -m unittest test_cascade.py
```

The tests compare joint threshold search with brute-force enumeration including
tied scores, verify four fixed-policy corners and sunk weak-call costs, and
verify feature extraction ignores gold/outcome metadata. The experiment also
cross-checks every locked validation operating point by direct composition.

## Regenerate the complete grid on four local GPUs

`deployment/cascade_four_gpu.py` shards instance IDs across GPUs 0/1/2/3.
Each GPU generates weak and strong retrieval, followed by weak and strong
answers on both retrieval branches. It records output text and actual token
counts, recomputes the four outcome cells, creates matching new labels and
six mean token-aware costs, and automatically runs `cascade.py` with weak
answers after successful generation. Checkpoints and errors are recorded
under the output directory; a worker failure stops the other workers.

This run uses FP16 Instruct weights, greedy decoding, the provided first 100
passages in their existing order, and a 600-character passage cap. No gold
passages are inserted at inference. Calls exceeding 16,384 input tokens fail
rather than being silently truncated. The archived grid runner supplies its
retrieval/QA prompt and parsing functions. The original final grading script
is missing; the new run explicitly records its local exact-match and guarded
whole-word containment scoring rules. This is a new experiment using the
cascade method, not a numerical reproduction of the author's published result.

The isolated environment is `${WORKSPACE}/.cascade-env` (existing Torch
and sklearn packages plus Transformers 4.57.1 and Accelerate 1.10.1).
Instruct HF weights are under `models/Qwen2.5-{1.5B,7B}-Instruct-HF`.

```bash
cd ${WORKSPACE}
env OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  .cascade-env/bin/python -u STAIR/nonLLM/deployment/cascade_four_gpu.py \
  --out ${WORKSPACE}/runs/nonllm_cascade_four_gpu_full_v1
```

Use `--limit 2` with a separate fresh output directory for the four-GPU smoke
check (eight questions, 48 calls; no router training). Full progress is in
`status.json`, `shard_*/status.json` and `gpu_*.log`. Final router results
are in `router/REPORT.md` and `router/results.json`.

Set `WORKSPACE` to the directory containing the STAIR checkout and local experiment data before using these example commands.
